# 검증과 완료 판정

| 구간 | 반드시 남길 근거 |
|---|---|
| 문서/연결 | 원문과 정정, R-ID, 파일·테스트·증거 매핑, 승인 내용 hash와 인증된 원본 |
| 공용 하네스 | 설치 커밋, 실제 로드한 스킬/훅 버전, 새 환경 결과, 변경 전후 eval |
| 자료 | 사람별 설치/인증/읽기, 실제 sample ID, 조회시각, revision/hash, 첨부·이미지·페이지 누락 |
| CI | 정확한 후보/기준 SHA, runner/도구 버전, 명령·종료값·테스트 개수·실패/skip, 원시 artifact |
| 독립 리뷰 | 다른 작성/리뷰 session ID, 입력 diff/spec 버전, 지적·재현·처리, 미해결 차단 사항 |
| 실제 DEV | 실행 전후 서비스 조합 SHA/digest, 환경 lease, 실제 사용자/API 경로, 데이터 정리 |
| 운영 전환 | 사람 승인 대상 환경/SHA/위험/복구, 실제 자격 분리, 거부/허용 경로, 결과불명 복구 |

## 재실행할 샘플

1. 정상 요청 → spec → plan → tests → 독립 리뷰 → 판정.
2. 요청자의 정정과 원자료 충돌: 이전 결정이 조용히 살아 있지 않은가.
3. 자료 첨부/하위 페이지 접근 실패: 실제 누락을 표시하는가.
4. 테스트 실패, 빈 결과, skip, 알려지지 않은 모델 버전: 완료를 거부하는가.
5. 다른 커밋의 성공 결과, 승인 후 문서/코드 변경: 오래된 증거와 승인을 무효화하는가.
6. 후보가 필수 검사를 지우거나 gate를 약화한 경우: 신뢰된 판정기가 거부하는가.
7. 사람 담당자의 본인 승인과 작성 에이전트의 자기 리뷰를 구분하는가.
8. 다른 팀원이 기록·핀된 도구로 작업을 이어받을 수 있는가.

보호 코드를 제거하는 변이 실험은 격리된 fixture에서 수행한다. 원격 운영 환경에서 결함을 주입하지 않는다.
이 샘플들의 성공은 모의 절차 검증이다. 실제 계정·원격 인증·운영 차단의 증거를 대체하지 않는다.

## 상태를 구분한다

- PASS: 필수 검사와 실제 대상 버전의 성공 증거가 있다.
- FAIL: 실행한 검사가 실패했다.
- BLOCKED: 필요한 자격/데이터/서비스가 없어 실행할 수 없다.
- NOT_RUN: 아직 실행하지 않았다.
- N/A: 승인된 정책에서 해당 작업에 필요하지 않다고 결정했고 이유가 있다.

실행 전 정의한 필수 목록으로 판정한다. 후보 PR이 자기 목록을 줄일 수 없게 한다.
로컬 정적 검사 PASS는 파일 정합성뿐이다. 공유 CI·사람 승인·원격 실행을 증명하지 않는다.
보고는 실패 원인과 남은 사람 작업을 구체적으로 밝히고, 막히지 않은 승인 범위의 작업은 계속한다.
목표가 기록·CI·사람 수동 승인이라면 그 실제 절차를 검증한다. 선택하지 않은 승인 서버·패스키·자격 회수를 새 완료 조건으로 추가하지 않는다.
