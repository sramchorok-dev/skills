# 기존 프로젝트 전환

## 읽고 고정할 것

저장소별 원격 기본 브랜치/HEAD, 배포 트리거, 열린 PR, worktree와 변경 중 파일을 기록한다.
부모 폴더와 repo의 AGENTS/CLAUDE, 전역/팀 플러그인, hooks, CI, Code Owners, 배포 자격을 조사한다.
같은 문구가 여러 경로에서 활성화되는지 확인한다. 실제 DB changeset checksum 같은 실행 제약은 단순 팀 선호 규칙과 구분한다.

## 규칙 교체

각 기존 파일/규칙을 `교체`, `이관`, `폐기`, `역사보존`으로 분류하고 대체 위치와 이유를 적는다.
바꾸기 전 원본 바이트와 SHA-256을 저장한다. 사용자의 미커밋 수정도 보존 대상이다.
새 버전을 별도 worktree에서 준비하고 검증한다. 적용 직전 원본 hash가 그대로인지 확인한다. 달라졌으면 새 변경과 병합한다.
활성 진입점에서는 새 정본 하나를 가리키고, 옛 기록은 비활성 역사 폴더로 보존한다. 전체 디렉터리 삭제나 다른 작업의 reset/stash로 정리하지 않는다.
생성기는 기존 파일을 덮지 않으므로 빈 초안 폴더에서 생성한 뒤 승인된 파일을 하나씩 반영한다.

## 적용 순서

공용 정책/실행 코드 → 샘플 dry run → 사람별 설치/자료 인증 → 실제 공용 CI/DEV → 서비스별 적용 → 승인된 자격/배포 경로 전환.
사용자가 시범 운영을 제외했으면 장기 pilot 단계를 추가하지 않는다. 절차 샘플 검증과 실제 운영 적용을 구분한다.
기존 PR에는 전환 기준을 적용할 시점을 기록하고, 오래된 증거를 새 버전의 증거로 재사용하지 않는다.

## 전환 패킷

대상 repo/환경/계정, 기존/신규 SHA, CI·DEV·리뷰 링크, 남은 사람 등록, 구체적 실행/복구 명령, 비용을 묶는다.
운영 자격 회수는 실제 승인 경로가 검증된 뒤 진행한다. 승인받은 범위의 가역 준비는 미리 마친다.
개인 패스키/OAuth는 해당 사람이 직접 등록한다. 다른 사람 계정으로 대체하거나 쿠키를 공유하지 않는다.

## 복구

이전 검증 버전과 설정을 복원할 수 있어야 한다. 다만 회수한 에이전트 운영 권한이나 승인 없는 자동 운영 배포를 되살리지 않는다.
안전한 이전 버전이 없으면 변경 실행을 멈추고 사람 관리 절차로 복구한다. 승인·업무·증거 이력은 보존한다.
모든 대상의 실제 확인이 끝나기 전에는 전체 전환 완료라고 보고하지 않는다.
