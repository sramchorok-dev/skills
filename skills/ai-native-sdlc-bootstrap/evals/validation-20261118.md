# 실제 모델 계획 평가 · 2026-11-18

합성 요청 3종을 스킬 사용/미사용으로 각각 실행했다. 실제 저장소·계정·배포 작업은 수행하지 않고 계획 응답을 평가했다.
CLI는 2.1.326, 최종 3쌍의 관측 모델은 모두 `claude-fable-5-2`였다. 각 페어는 모델이 같고 세션 ID가 다르다.
스킬 사용 세션 3개는 정확한 namespace 호출과 같은 tool ID의 성공한 결과를 확인했다. 미사용 세션은 도구 호출이 없었다.

| 사례 | 평가 기준 수 | 스킬 사용 | 현재 모델 기본 응답 |
|---|---:|---:|---:|
| 단일 저장소 사내 도구 | 5 | 5 | 4 |
| 미커밋 규칙이 있는 3개 저장소 전환 | 5 | 5 | 3 |
| 오래된/빈 증거·미등록·잔존 관리자 자격 | 4 | 4 | 3 |
| 합계 | 14 | 14 | 10 |

독립 에이전트가 evals.json의 rubric과 응답 인용으로 채점했다. 비블라인드 평가이며 각 사례를 한 번씩 비교했다.
첫 실행에서는 “도구를 실행하지 말라”는 입력이 Skill 읽기까지 막아 1개 세션이 스킬을 읽지 않았다. 입력을 “스킬 읽기 외 작업 도구 금지”로 명확하게 했다.
두 번째 실행의 스킬 사용 결과는 13/14였다. 기존 미커밋 파일 보존 계획이 빠져, 원본 바이트/hash 보존→별도 초안→적용 직전 hash 재대조 원칙을 SKILL 본문에도 넣었다.
최종 결과는 반복 평가한 입력이다. 새 held-out 데이터나 일반적인 신뢰도/성능 우위를 증명하지 않는다.
빈 설정에서도 builtin/관리형 plugin이 보일 수 있으므로 완전한 무설정 baseline이라고 부르지 않는다. 다른 Skill 사용은 관측되지 않았다.

## 결정적 검증

- 생성기 18개 + 모델 실행 증거 검사 4개 = 22개 회귀.
- 생성된 요구사항 연결 게이트 15개 회귀, 정상/실패 dry run 8개.
- 독립 리뷰에서 빈 R 제목이 다음 R을 삼키던 결함을 발견해 행 단위 검사로 수정했다. 잘못된 제목/ID·CRLF·공백 회귀를 추가했다.
- Unknown Skill 오류를 성공한 로드로 계산하던 평가 실행기 결함을 수정했다. 실제 성공 tool_result와 페어의 모델·세션 identity를 확인한다.

재실행: `python3 scripts/run_model_eval.py --output /absolute/new-directory`.
원시 JSONL과 review.html/results.json은 해당 디렉터리에 저장한다. 로컬 경로가 들어갈 수 있어 기본 비공개 보관하고, 공유할 때 필요한 결과만 추린다.
