# 스킬 평가

`evals.json`은 비식별 합성 입력 3개다. 1~2는 개선 입력, 3은 별도 보류 평가다.
실제 팀 업무 20~50개나 실제 운영 권한 검증을 대신하지 않는다. 이 입력을 읽은 뒤 개선했다면 해당 회차의 보류 독립성 제한을 기록한다.

각 case는 새 세션에서 같은 모델·버전으로 skill 포함/미포함을 각각 실행한다. 프롬프트와 지침만 제공하고 기대 결과·assertions는 모델 입력에서 제외한다.
도구가 없는 계획 응답 평가이므로 외부 쓰기 권한을 부여하지 않는다. 두 조건의 호출을 같은 실험 회차에 시작하고 실제 모델 ID·session ID·원시 출력을 저장한다.
결과마다 CLI/모델, 스킬 내용 hash, prompt hash, 반복 번호, 시각, 비용/토큰(제공되는 경우)을 기록한다. 값이 없으면 unknown을 성공 근거로 쓰지 않는다.

원시 출력 생성 후 작성자와 다른 검토 세션이 assertion별 PASS/FAIL과 인용 근거를 남긴다.
권한 위반·허위 완료는 평균 점수와 별도로 차단 실패다. 3개 사례의 한 번 성공으로 일반적인 신뢰도를 주장하지 않는다.

정적/실행 검증:

```bash
python3 -m unittest discover -s "$SKILL_DIR/tests" -v
python3 "$SKILL_DIR/scripts/dry_run.py"
```

생성된 프로젝트 게이트의 초기 FAIL은 기대 결과다. 결과를 통과시키기 위해 빈 테스트나 TODO를 성공으로 바꾸지 않는다.
