# 디자인 일치 검증 — 수동 browser-use

디자인과 실제 화면을 대조하거나 디자인 불일치의 재발 방지를 요청받으면 이 절차를 실행한다.
이 절차는 `browser-agent.md`의 증거·판정·격리 규칙을 추가로 따른다. CI나 스케줄러에서 브라우저를 실행하지 않는다.
기능 테스트 PASS나 구현에서 만든 스냅샷은 Figma 일치의 증거가 아니다.

## 1. 출처와 범위를 먼저 고정

1. 서비스 저장소의 `docs/design/SOURCE-MAP.md`와 최신 QA 시트를 읽는다. 시트는 실행할 때 다시 조회하고 조회 시각·원본을 private 경로에 남긴다.
2. Figma 로그인 후 정본 프레임을 실제로 연다. 페이지 이름의 날짜만 믿지 않는다. 파일·노드 ID, 읽은 시각, 현재 내보낸 이미지와 Dev Mode 수치를 저장한다. 예전 XML은 노드 탐색용으로만 쓴다.
3. `figma-manifest.json`의 **모든 화면/상태**와 시트 모든 행을 합친다. 시트 밖 런칭 화면, 팝업·오류·빈 화면·로딩, 결제 전/검토 중/확정본, 로그인/가입을 빼지 않는다. PC·모바일은 각각 독립 셀이다. 같은 프레임을 반복하는 시트 행도 추적 ID를 보존한다.
4. 각 셀에 경로·상태 재현 절차·fixture·Figma 노드·실제 뷰포트·담당 코드·검증 항목을 연결한다. make/fixture/원본이 없어도 범위에서 제거하지 않고 BLOCKED로 남긴다. 출처 충돌은 일치로 덮지 않는다.
5. 공용 컴포넌트·폰트·색·표시 데이터·이미지가 바뀌면 모든 소비 화면을 포함한다. 영향 매핑이 없으면 전체를 대상으로 잡는다. 전체 선언 뒤 선택 범위를 좁힌 실행은 부분 실행으로 보고한다.

## 2. 한 셀의 합격 기준을 요소별로 작성

아래 항목은 범주 이름만 쓰고 PASS 처리하지 않는다. **실제 요소 선택자/텍스트와 독립적인 기대값**으로 쪼갠다.

| 범주 | 기대값·관찰값 |
|---|---|
| 구성·순서 | 헤더부터 푸터까지 모든 섹션, 숨김 요소, 중복 링크, 상태별 CTA |
| 문구·데이터 | 문장·공백·단위, 실제 API의 수량/금액/날짜, 빈 값의 안내 |
| 글자 | font-family/size/weight/line-height/letter-spacing/color, 줄바꿈 |
| 배치 | 컨테이너 폭, gap/padding/margin, 정렬, breakpoint, 고정 막대 |
| 표면 | 배경·테두리 색/두께, radius, 그림자, 상태 색 |
| 이미지 | 원본 자산, 크기/비율, contain/cover, 잘림, 모바일 스크롤, 로딩 완료 |
| 동작 | 링크 목적지, 열기/닫기/뒤로/재시도, 키보드 접근, 동의·저장·결제 경계 |

- 정적 글자·색·서체·간격은 기대값과 실측값을 비교한다. 임의로 허용 오차를 넓혀 통과시키지 않는다. 브라우저 소수점 반올림과 안티앨리어싱 차이는 따로 설명하며 레이아웃 차이와 혼동하지 않는다.
- 데이터 예시값은 Figma 값을 운영 화면에 하드코딩하지 않는다. 고정 QA fixture와 API 응답으로 독립 검증하고, 데이터가 달라도 레이아웃·단위·누락을 검사한다. 숫자가 포함됐다는 이유만으로 문장 전체를 검증 제외하지 않는다.
- 승인된 정책이 Figma보다 우선하면 정확한 결정·범위·날짜를 연결해 `결정으로 다름`으로 별도 보고한다. 이를 `디자인 완전 일치`라고 부르지 않는다. 원인 불명 차이는 FAIL이다.

## 3. Ego에서 실제 관찰

1. 현재 사용자 승인 프로필·작업 공간과 실제 역할을 기록한다. 새 탭을 격리 세션이라고 하지 않는다. 계정·장바구니를 임의로 지우지 않는다.
2. 실제 배포 revision·환경을 저장한다. 수동 browser-use는 API 응답 대체나 토큰 주입을 하지 않는다. 별도의 자동화 fixture 검증은 명확히 구분한다.
3. UI로 해당 상태에 진입한다. Figma와 같은 폭에서 상단부터 하단까지 스크롤해 지연 로딩된 사진·폰트가 완료됐는지 확인한다. 깨진 이미지·콘솔 오류·가로 넘침을 먼저 기록한다.
4. 전체 페이지 및 섹션 캡처, DOM 문구와 computed style/좌표를 저장한다. Figma 원본과 실제 캡처를 둘 다 열어 나란히 대조한다. 스크린샷을 생성했지만 보지 않은 것은 시각 검증이 아니다.
5. 체크마다 기대값·관찰값·Figma 증거·실제 증거·MATCH/MISMATCH/UNKNOWN을 남긴다. 첫 실패와 재시도 증거를 덮어쓰지 않는다.
6. 같은 컴포넌트의 다른 상태와 PC/모바일을 이어 검증한다. 중간 폭은 가로 넘침·숨김·클릭 가능 여부를 추가 검증한다. Chromium 모바일 폭은 실제 iOS 검증과 구분한다.

## 4. 재검증 및 완료 판정

- 구현 수정 뒤 해당 셀과 공용 소비 셀을 새 revision으로 다시 실행한다. 출처/카드/revision 변경 시 새 run을 만든다.
- 기존 `browser_agent.py record/summary`를 사용해 항목 누락·증거 없음·버전 불일치를 거부한다. private 서비스의 `figma:coverage`는 매핑만, `qa:selfcheck --strict`는 수치 보조 검증만 증명한다. 미실행·건너뜀·누락·오류는 PASS가 아니다.
- 공개 화면만 검증한 결과로 인증·주문·확정 리포트까지 완료했다고 하지 않는다. 전체 캡처 하나로 팝업·실패 상태 검증을 대신하지 않는다.
- 머지/배포 요청이 있으면 completion-qa에 이 수동 결과를 연결한다. 배포 후 실제 revision을 다시 확인하고 변경된 핵심 경로를 관찰한다. 수동 suite를 CI나 자동 배포 스크립트에 연결하지 않는다.
- 최종 보고: 선택/전체 셀 수, PASS/FAIL/BLOCKED/NOT_RUN/결정으로 다름, 기능/시각/실기기 검증 구분, 원본 날짜·revision, 남은 결함과 근거 링크. 필수 셀이 남으면 NOT COMPLETE.

## 잘못된 통과를 막는 예

- CSS 테스트 100건 통과 + Figma 미열람 → 디자인 NOT_RUN.
- 90개 중 80개에 make 있음 → 80개만 검사했다고 적고 나머지 10개 BLOCKED.
- 최신 시트에서 4행 추가 → 목록 갱신 후 새 실행. 이전 범위 PASS로 종료하지 않음.
- 화면은 맞지만 저장 약속이 실제 동작과 다름 → 동작 FAIL. 디자인 문구 그대로 복사해 해결하지 않음.
- 결제 완료 fixture 없음 → 해당 셀 BLOCKED, 독립적으로 가능한 로그인/공개 화면은 계속 실행.
