# 브라우저 실행 요령

쓸 수 있는 브라우저 도구(Playwright, Claude in Chrome, 다른 브라우저 자동화)를 쓴다. 도구가 없으면
사용자에게 알리고 화면 확인이 필요한 TC는 BLOCKED(브라우저 도구 없음)로 둔다.

## 세션과 화면 크기

| 카드 표기 | 설정 |
|---|---|
| PC, 1280px, 데스크톱 | 1280×720 |
| 모바일, 390px | 390×844, 터치·모바일 UA |
| 360px | 360×780 |
| 1440 | 1440×900 |

- TC마다 새 컨텍스트(시크릿과 같음)에서 시작한다. 이전 TC의 로그인·장바구니가 남으면 결과가 오염된다.
- `파라미터/뷰포트` 칸에는 크기와 브라우저를 함께 적는다. 예: `모바일 390×844 · Chromium 새 세션`.

## 화면이 준비됐는지 기다리기

- 첫 화면은 그려졌어도 아직 클릭이 안 먹을 수 있다(하이드레이션 전). 느린 회선에서는 10초 넘게 걸린 적이
  있다. 클릭이 반응하지 않으면 "기능 안 됨"으로 판정하기 전에 네트워크가 잠잠해질 때까지 기다리고
  한 번 더 시도한다. 두 번째도 반응이 없을 때만 불일치로 적는다.
- 고정 시간 대기보다 "기대한 문구·요소가 보일 때까지" 기다린다.
- `alert`/`confirm` 창이 뜨는 동작은 창을 받을 준비를 먼저 하고 클릭한다. 창 문구도 기준 항목이면
  글자 그대로 적는다.

## 문구 확인

- 화면 문구는 DOM의 `innerText`로 가져와 비교한다. `textContent`는 줄바꿈·숨은 글자·요소 사이 공백이
  화면과 달라질 수 있다. 띄어쓰기 하나로 판정이 갈리면 스크린샷과 한 번 더 대조해 observed에 화면 그대로 적는다.
- 기준에 따옴표로 된 문구는 **글자 그대로** 같아야 일치다. 띄어쓰기·마침표·물결표가 달라도 불일치로 적고,
  observed에 실제 문구를 그대로 쓴다. 판단은 사람이 한다.
- 개수 기준("GNB 4개", "탭 5슬롯")은 실제 개수와 이름을 모두 적는다.

## 스크린샷

- 항목마다 한 장 이상. 이름: `shots/<Run ID>/<TC>-<pc|m>-<C번호>.png` (예: `shots/QA-20261010-01/A-02-m-C1.png`)
- 개인정보(전화번호·이메일·주소·주문 토큰)가 화면에 있으면 가리고 찍거나 그 부분을 잘라 낸다.
- 시트의 `증거 링크` 칸에는 이 파일을 올린 공유 폴더 주소를 사람이 넣는다. JSON의 `evidence_folder`에
  폴더 주소를 알면 적는다.

## 관리자 화면

- 관리자 TC는 별도 컨텍스트에서 관리자 계정으로 로그인한다. 고객 세션과 섞지 않는다.
- 관리자에서 저장·확정·발행 버튼은 TC 절차에 있는 것만 누른다. 상품 가격·재고·진열 토글은 건드리지 않는다.
