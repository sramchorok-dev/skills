# /ship-pr

현재 브랜치의 변경을 팀 규칙에 맞춰 PR로 만든다. 단계마다 결과를 한 줄씩 보고하고, 실패하면 그 단계에서 멈춘다.
`$ARGUMENTS`에 `--ready`가 없으면 draft PR로 연다.

## 0. 전제 확인

- 레포 루트에서 실행 중인지, 현재 브랜치가 `main`·`dev`가 아닌지 확인한다. 아니면 멈추고 새 브랜치를 제안한다.
- `git fetch origin` 후 기준 브랜치(`origin/dev`, 없으면 `origin/main`)와의 diff를 확인한다. 변경이 없으면 멈춘다.
- 커밋 안 한 변경이 있으면 목록을 보여 주고, 포함할지 사용자에게 묻는다.

## 1. 테스트 점검

`gardenstep-test-audit` 스킬로 `--working-tree` 점검을 한다. 판정이 FAIL이면 고칠 항목을 보여 주고 멈춘다.
WARN이면 항목을 보고하고 계속한다. 실제 테스트 실행 증거가 필요하면 `gardenstep-completion-qa`의 해당 단계를 따른다.

## 2. 변경기록

`gardenstep-change-log` 스킬로 `docs/changes/` 기록을 만들거나 갱신한다.

- `## 무엇이 바뀌었나`는 diff를 보고 동작 중심으로 초안을 쓴다.
- `## 왜`는 대화·이슈(`$ARGUMENTS`)에 이유가 있을 때만 쓴다. 없으면 **사용자에게 한 문장으로 묻고 기다린다.**
- ADR 기준(되돌리기 비쌈·여러 레포 영향·검토한 대안 중 둘 이상)에 맞으면 ADR 작성을 제안한다. 쓰지 않으면 `adr: none`.
- `check`가 통과할 때까지 고친 뒤 기록을 커밋한다.

## 3. PR 본문

임시 파일에 본문을 쓴다. 첫 문장은 **문제 → 달라진 동작**이다.

```markdown
<문제와 달라진 동작 1~3문장>

## 검증

- <조건 → 기대 동작>: <테스트 방식·환경·결과> — `<테스트 파일>`
- 결함 감지: <무엇을 고의로 망가뜨리자 어떤 테스트가 실패했는지>

## 변경기록

`docs/changes/YYYY/YYYY-MM-DD-<branch>.md`
```

`## 검증`에는 이번 세션에서 실제로 실행해 본 것만 쓴다. 실행하지 않은 것은 `미확인:`으로 적는다.

## 4. PR 생성

```bash
git push -u origin HEAD
gh pr create --base dev --title "<달라진 동작 한 줄>" --body-file <본문 파일> [--draft]
```

PR 게이트 hook이 확인을 요청하면 표시된 항목을 먼저 채운다. 사용자가 그대로 진행을 승인한 경우에만 계속한다.

## 5. 마무리

- `change_record.py set-pr --pr <번호>`로 기록에 PR 번호를 채우고 커밋·push한다.
- PR URL, 테스트 점검 판정, 변경기록 경로, ADR 판정, CI 상태를 보고한다. 머지는 하지 않는다 — 머지는 CI 초록 + JD 승인 후 사람이 한다.
