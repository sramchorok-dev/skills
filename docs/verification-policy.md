# 빠른 배포와 검증 상태 — DEV 시범 운영

상태: **DEV 시범 적용**, 팀 정본 PR의 병합·전체 팀원 설치와 운영 전환은 별도다. 결정은 [ADR 0007](adr/0007-dev-fast-deploy-qa-pilot.md)을 따른다.

## 배포와 검수

- DEV: 짧은 변경·환경·revision 검토 → 빌드 → 배포 → 기동/revision 확인. 전체 회귀·E2E·에이전트·Figma 검수는 사후 또는 전용 검수 스킬에서 수행한다.
- BE·FE·AI DEV 저장소에 사후 QA 및 실패 알림 경로가 적용되었다. 새 환경에서는 실제 워크플로 배선·실행 증거를 확인한다. 로컬 배포 outbox/worker는 관리자 개인 설치이며 이 팀 스킬 설치가 배포 worker를 설치하지 않는다.
- 운영: 기존 필수 CI·승인·DB 변경 및 롤백 절차를 유지한다. DEV 성공이나 이 문서만으로 main 머지·운영 실행을 승인하지 않는다. 구체적인 대상 SHA와 범위를 제시한 뒤 사용자의 운영 배포 지시에 따라 실행한다.

## 로컬 검수 책임

훅은 UI 영향 후보를 로컬 큐에 접수한다. 실제 검수는 `gardenstep-qa-run`에서 실행한다. 자동 실행이나 중앙 감시를 의미하지 않는다.

1. 작업자가 `qa_queue.py assign`으로 담당자, 시간대가 있는 기한, 팀 GitHub PR/issue 링크를 지정한다. 공유 링크를 입력하는 것만으로 원격 글이 갱신되지는 않는다.
2. PR 작성자는 `qa_queue.py handoff` 결과를 PR의 `## 검증`에 포함한다. 검수 담당은 결과가 바뀔 때 같은 공유 기록을 갱신한다. 이 작업은 PR 작성/갱신 권한 범위에서 수행한다.
3. 기본 기한은 DEV 배포 다음 영업일까지다. 범위가 커서 다른 기한이 필요하면 PR에 근거와 새 기한을 남긴다. 세션 시작·종료에서 미지정·기한 초과를 안내하며 배포를 차단하지 않는다.
4. 리뷰어는 공유 기록에서 미지정/기한 초과/차단 상태를 확인한다. 기한 초과는 담당자에게 재할당 또는 새 기한·사유를 요구한다. 종료 보고에는 미완료 항목을 숨기지 않는다.
5. 배포 성공과 QA 완료를 분리한다. 담당·기한·추적 링크가 없으면 QA PASS로 닫지 않는다. 원본·매핑·실행 증거 미확정은 BLOCKED다.

**보장 범위:** PC가 꺼져 있거나 세션이 없으면 로컬 알림은 발생하지 않는다. 중앙 자동 감시를 구현한 것으로 보고하지 않는다. 서버 사후 QA의 Telegram 실패 알림은 이 로컬 디자인 큐와 별개다. 팀 공유 기록의 확인은 리뷰어 책임이다.

## 디자인 검수 적용

- 시각 변경: 승인된 원본 URL·버전과 영향 화면을 개발 전에 확인하고, 실제 화면과의 비교는 사후 또는 전용 검수 시 수행한다.
- 비시각 변경: 매핑에 `design: not-applicable`과 구체적 사유를 기록한다. Figma 증거만 제외되며 관련 기능 검수 cards/viewports와 QA 실행 증거는 유지한다. 생략 사유는 PR 리뷰 대상이다.
- 각 매핑 규칙의 카드×viewport, 노드×viewport×checks를 유지한다. 관계없는 화면과 viewport의 조합을 만들어 요구하지 않는다.
- `status`의 UNVERIFIED는 실행 환경 문제로 현재 재검증할 수 없다는 뜻이다. 저장된 과거 PASS를 새 검증 통과라고 보고하지 않는다. Pillow/도구 환경을 복구한 뒤 다시 확인한다.

## Claude·Codex 범위

공통: 같은 skills·AGENTS.md와 QA 접수/인계 계약. QA 어댑터는 두 도구에 SessionStart/Stop만 연결한다.

Claude 플러그인의 편집 보호·Bash 확인·PR 게이트는 별도 기능이다. Codex에 동일한 강제력이 설치됐다고 표현하지 않는다. 팀 필수 변경기록/테스트 규칙의 공통 검사는 서비스 CI의 change-gate/test-gate를 기준으로 하며, 설치만으로 CI나 브랜치 보호가 추가되지는 않는다. 새 레포는 실제 CI 배선을 먼저 확인한다.

## 기록

PR `## 검증`: 변경 범위, 실제 실행 증거, 미완료 항목의 담당·기한·추적 링크. 예: `배포: DEV SHA… 확인 / QA: Figma BLOCKED, 담당…, 기한…, 사유…`.
변경기록의 `pr: null`은 유효하다. 번호 채우기를 위한 별도 커밋은 불필요하다. ADR/changes는 [ADR 0006](adr/0006-adr-rules-enforced-by-ci.md)을 따른다.
