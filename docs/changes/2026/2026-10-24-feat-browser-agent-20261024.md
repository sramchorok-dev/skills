# 수동 브라우저 E2E 카드와 증거·커버리지 기록기를 제공한다

## 무엇이 바뀌었나

- 버전 있는 카드 선택·초기화·revision 확인 재개·항목별 증거 기록·분모 유지 집계·생성 자원 정리 원장을 제공한다.
- 코드 기반 결정적 CI 검사를 대체하지 않는 수동 browser-use 모드를 안내하고 팀 CI 선택/재사용 조건을 정리한다.
- 기존 시트 모드와 PR7 API matrix/copy 도구를 보존한다.

## 왜

JD가 2026-10-24 주요 기능을 필수 포함하고 최대한 넓은 computer/browser use E2E를 CI에 넣지 않고 스킬로 실행하기 원했다. 조사 계획에 “너가 생각하는 방향으로 전부 진행하자”라고 승인했다.

## 확인한 것

- catalog 스키마·335행 매핑·103TC/P0 49·24여정·FE58/Admin47·200조합 재생성 확인.
- 공용 toolkit 새 regression33 + 기존29 통과, 저장소 테스트46 통과. 기준누락·없는/변조증거·revision/source 변경·조기실패·격리·분모를 검증했다.
- 독립 최종 코드·corpus 리뷰 APPROVE(2026-10-25). egolite 전용 짝지은 스킬 eval 3쌍과 독립 평가를 완료했다. 모든 런의 실제 브라우저 검수는 실행 환경 제약으로 BLOCKED이며 false PASS는 없었다. 항목 충족은 신규11/16·기존10/16로, 작은 표본의 기술적 비교이며 통계적 우위를 뜻하지 않는다. 실제 제품 여정은 부분 관찰이다. 이 기록은 제품 전체 QA 완료가 아니다.

- 독립 리뷰의 원문누락·N/A은폐·정리증거 부재를 RED5→GREEN 회귀로 수정하고, 과거 결함 관찰을 목표값으로 변환하지 않도록 corpus 회귀9건을 추가했다. fixture-check는 실제 준비 증거를 검사하며 준비를 대체하지 않는다.

- private corpus 재검토2에서 원문 TC의 Admin/AI revision 의존과 DB 전용 보조 검사 경계를 추가 검증했다(회귀2건 RED→GREEN).
