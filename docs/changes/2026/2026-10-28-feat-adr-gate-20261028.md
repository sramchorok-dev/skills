# ADR·변경기록 남발을 CI가 막고, 레포 간 히스토리를 한곳에서 검색한다

## 무엇이 바뀌었나

- `change-gate`가 새 ADR의 기준(둘 이상)·형식·분량·번호와 채택된 ADR의 몰래 수정, 변경기록 `adr:` 상호 참조를 검사한다. 위험도 높은 변경이 `adr: none`이면 경고한다.
- 변경기록 `## 왜`가 상투어나 10자 미만이면 실패한다.
- `new-adr`로 다음 번호의 ADR 초안을 만들고, `history.py`로 세 레포의 변경기록·ADR을 검색한다.
- `new`가 마이그레이션 변경을 감지하면 `risk: migration`·`rollback: rds-snapshot`을 미리 채우고, 사람이 채울 칸을 안내한다.
- ADR을 쓰지 않기로 한 판정을 `adr: none (기준 1개: 이유)`로 기록에 남기면 위험도 경고가 사라진다.

## 왜

- JD 요청(2026-10-28 대화): ADR과 changes를 문서로 관리해 히스토리를 찾되, 남발하지 않도록 명백한 룰과 이를 확인하는 CI가 필요하다.

## 확인한 것

- skills 저장소 CI 4종(validate_skills, 플러그인 버전, 저장소 테스트 46개, 스킬 테스트)을 로컬에서 통과.
- 문서만 읽은 독립 에이전트(마이그레이션 변경 시나리오, 결정자·대안 미제공)가 `new`→`check` 통과까지 수행했고 ADR을 지어내지 않았다. 지적된 빈틈(판정 미기록, 기준 세는 법, `new`의 마이그레이션 미감지)을 반영했다.
- 기존 ADR 0001~0004는 새 규칙에서 `기준` 줄 외에는 모두 통과(옛 ADR에는 소급 적용하지 않음).
