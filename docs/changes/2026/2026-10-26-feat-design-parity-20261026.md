# 디자인 검증에 최신 원본과 전체 상태의 실제 화면 증거를 요구한다

## 무엇이 바뀌었나

- gardenstep-qa-run에 디자인 일치 전용 절차를 추가한다. 시트 밖 런칭 화면·미작성 절차도 범위에 남기고, 각 요소의 Figma 값과 실제 관찰을 연결한다.
- 이미지 지연 로딩·반응형·동작·소스 충돌을 포함하고, 기능 테스트 성공과 시각 검증을 구분한다. 변경된 원본이나 revision에는 새 실행이 필요하다.
- 기존 browser_agent 결과 기록기를 사용한다. 브라우저 실행을 CI나 자동 배포에 추가하지 않는다.

## 왜

JD가 반복된 디자인 불일치를 확실히 고치고 재발을 막는 검증 프로세스를 만들어 실행하라고 지시했다(2026-10-26).

## 확인한 것

- validate_skills 통과. 기존 실행·판정 회귀 62건, 루트 테스트 46건 통과.
- eval 301에 최신 시트 추가 행·미작성 절차·시트 밖 화면·기능 PASS 오용을 포함했다. 실제 모델 평가와 변경 UI의 수동 실행은 별도 증거가 필요하다.
- 제품 화면 일치를 이 문서 변경의 통과로 주장하지 않는다.
