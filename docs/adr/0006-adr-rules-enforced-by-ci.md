# 0006. ADR 남발 방지 규칙을 `change-gate`가 검사하고, 기록은 레포에 두되 조회는 모은다

- 상태: accepted
- 날짜: 2026-10-28
- 결정: JD
- 기준: 넓은 영향 · 대안 검토

## 맥락

ADR 기준(둘 이상 충족)과 변경기록 형식은 문서로만 있었고, CI는 변경기록의 존재만 봤다. ADR이 남발되거나 기준 없이
추가되는 것, 채택된 ADR을 몰래 고치는 것, 변경기록 `## 왜`가 "개선" 한 단어로 채워지는 것을 막을 곳이 없었다.
히스토리를 찾으려면 레포 세 곳을 따로 뒤져야 했다. 서비스 3개 레포가 `main`의 skills를 받아 쓰므로 규칙은 한 곳에서 배포된다.

## 결정

- 규칙은 사람 판단이 아니라 파일에서 기계가 읽을 수 있는 형태로 둔다: ADR 헤더 `- 기준:`에 충족한 기준 둘 이상을 적는다.
- `change_record.py check`(= CI `change-gate`)가 ADR 규칙을 함께 검사한다: 기준 둘 이상, 다음 순번, 필수 칸, 대안 표, 다시 볼 조건,
  80줄 이하, 채택된 ADR은 상태 줄만 수정, 변경기록 `adr:`와 PR이 추가한 ADR의 상호 참조. 새로 추가한 ADR에만 적용한다.
- 변경기록 `## 왜`는 10자 미만이거나 상투어뿐이면 실패한다(이슈 링크가 있으면 통과).
- 위험도 높은 변경이 `adr: none`이면 실패가 아니라 경고한다. ADR 필요 여부는 사람이 판단한다.
- 기록은 각 레포에 둔다. 한곳에서 찾을 수 있게 `history.py`로 조회만 모은다.

## 검토한 대안

| 대안 | 버린 이유 |
|---|---|
| ADR·변경기록을 중앙 저장소 한 곳에 | 0003에서 이미 버렸다. 변경마다 PR을 하나 더 내야 해서 지켜지지 않는다 |
| 문서 규칙만 두고 CI는 존재 여부만 | 지금과 같다. 남발과 몰래 수정을 막지 못한다 |
| ADR 필요 여부를 CI가 자동 판정(위험도 → 강제) | 판정이 틀리면 형식적 ADR을 양산한다. 경고까지만 한다 |
| 채택된 ADR을 자유롭게 수정 | 결정의 역사가 사라진다. 바뀌면 새 ADR로 대체한다 |

## 결과

- 좋아지는 것: 기준 없는 ADR과 몰래 수정이 머지 전에 걸린다. 레포 간 히스토리를 한 명령으로 찾는다.
- 감수하는 것: ADR 하나에 헤더 한 줄과 대안 표가 더 필요하다. `## 왜` 길이 검사는 형식만 막는다(내용의 진위는 못 본다).
- 다시 볼 조건: 3개월 안에 ADR이 기준 줄만 채운 형식적 문서로 늘거나, 정당한 PR이 규칙 때문에 반복해서 막힐 때.
