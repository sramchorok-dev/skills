# 0005. 수동 브라우저 인수 검수와 증거 기반 CI 선택

- 상태: 사용자 방향 승인(2026-10-24), 구현 독립 검증 중
- 결정자: JD — 주요 기능을 넓게 검수하는 browser-use 스킬과 CI 간소화 계획에 “전부 진행” 지시

실서비스 간 여정·UI 상태·외부 연동은 수동 browser-agent 스킬에서 검사한다. 카드/출처는 private 서비스 저장소,
계정/증거는 private runtime에 둔다. 공용 스킬은 선택·revision 고정·항목별 증거 판정·커버리지·정리 도구만 제공한다.
새 agent suite를 CI에 연결하지 않으며 코드 회귀 테스트를 대체하지 않는다.

CI는 핵심 결정적 검사와 영향 집합의 누락을 검증한다. 알려지지 않은/공통/민감 변경은 전체 fallback이며,
분류 결과와 선택/제외 이유를 남긴다. shadow 검증부터 시작한다. 성공한 동일 PR tree의 DEV push 재사용은
정확한 merge commit·동일 workflow·최신 필수 job 성공 증거가 있을 때만 허용한다. main·불명은 전체 실행한다.

대안: 모든 UI를 agent로 옮기면 금액·권한·경합 회귀가 비결정적이고 느려진다. 모든 기능을 매번 CI 전체+agent
전체로 반복하면 중복 비용이 크다. 선택 이유 없는 검사 삭제는 누락을 감춘다. 따라서 각 검증의 목적을 분리하고
변경 영향 선택은 보수적인 fallback과 결과 집계 계약으로 제한한다.

영향: 여러 서비스 저장소와 팀 테스트 정책에 적용. 실패/미실행을 숨기지 않는 artifact 계약을 유지하는 운영 비용이
추가된다. 도입 효과는 실제 PR 시간·runner 합계로 측정하며 구현만으로 절감률을 주장하지 않는다.
