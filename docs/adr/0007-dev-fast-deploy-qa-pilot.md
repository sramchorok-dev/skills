# 0007. DEV에서 빠른 배포와 사후 검증을 분리해 시범 운영한다

- 상태: proposed
- 날짜: 2026-10-31
- 결정: JD
- 기준: 되돌리기 비쌈 · 넓은 영향 · 대안 검토

## 맥락

JD는 배포 전 전체 테스트 대기를 줄이고 E2E·에이전트·Figma 검증을 사후 또는 전용 스킬로 분리하도록 요청했다. 이 변경은 여러 레포의 배포와 팀 작업 방식에 영향을 준다. 검증 누락 방지 기반이 완성되기 전에는 기존 게이트가 남아 있다.

## 결정

DEV에서 정확한 버전을 빌드·배포하고 사후 QA를 별도 추적한다. 로컬 Claude·Codex 훅은 QA 작업을 접수하며 검증을 수행했다는 증거가 아니다. UI는 개발 중 최신 디자인을 비교하고 운영 검증은 별도다. 실제 구현·검증되지 않은 부분은 대기 상태로 보고한다.

## 검토한 대안

| 대안 | 버린 이유 |
|---|---|
| 매 배포 전 전체 회귀를 기다린다 | 실측한 테스트 대기로 배포가 지연된다 |
| 사후 접수와 추적 없이 게이트만 제거한다 | 검증이 누락돼도 발견할 수 없다 |

## 결과

- 좋아지는 것: 배포와 검증의 시간과 상태를 구분한다.
- 감수하는 것: QA 대기·실패와 증거를 별도 추적해야 한다.
- 다시 볼 조건: 사후 검증이 누락되거나 동일 유형의 결함이 반복될 때.
